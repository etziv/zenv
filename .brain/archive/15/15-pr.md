M20 step 8a: native Studio window with file tree, editor and Go to file

Summary
- "Open in Studio" (app panel wide button, editor dropdown, actions menu) opens one native Studio window per app, a deferred
  egui viewport that keeps working while the main window hides in the tray.
- Header as in React: domain + project root, Go to file (Ctrl+P), Files toggle (Ctrl+B), preferred editor, project folder, browser.
- File tree with Material Icon Theme icons (one PNG atlas), lazy folders, new file/folder, refresh every 5 s and on focus.
- Editor: tabs with unsaved dot, VS Code Dark+ colours through syntect (re-coloured per changed line), line numbers, Ln/Col,
  Tab indents with the file's unit, Ctrl+S with the opened mtime, Load theirs / Keep mine on outside edits, clean files reload
  by themselves, CRLF kept, Ctrl+F find, gofmt/rustfmt/ruff format (+ on save, install missing), `.env` read-only.
- Closing a dirty tab, a Studio window, or quitting Zenv (tray Quit, main window without tray) with unsaved files asks first;
  the quit question names every Studio's unsaved files.
- Size limits from the risk gate: colours up to 100 KB with lines <= 2 KB, plain up to 1 MB, read-only above 1 MB or a 40 KB line.
- Find: Unicode case folding, hits cached, boxes only for visible rows.

Evidence
- `task.mjs check` passed; Studio tests 21 + QA tests 6 (incl. release measurements) passed; qa 2 rounds, security clean.
- Release measurement: typing median 12.4 ms (100 KB coloured), 15.0 ms (1 MB plain), 14.3 ms (1 MB with 17k find hits), 6.4 ms (20 KB minified); device run on C:\zenv-dev: 128 MB private.

Risks
- Studio windows have no screen-reader tree (eframe 0.37 wires accesskit to the root window only, G-019).
- No Prettier formatting and no CodeMirror extras (autocomplete, folding) in the native editor.
- New crates: syntect 5.3, fancy-regex, bincode.
