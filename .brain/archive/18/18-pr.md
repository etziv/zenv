M20 step 9: native-only Zenv, own NSIS installer, Tauri and React removed

## Summary
- `zenv.exe` is now the egui app (`src-native`, bin `zenv`); it runs the elevated hosts helper (`--zenv-apply-hosts`) before any
  GUI, as the Tauri main did. Icon and version info embedded with `embed-resource` (`src-native/build.rs`, `windows/zenv.rc`).
- New installer `installer/zenv.nsi`, built by `npm run installer` (`scripts/build-installer.mjs`, no tauri-cli). Same registry keys as
  the Tauri installer, so it upgrades C:\zenv in place; removes the Tauri `WebView2Loader.dll` and WebView data on upgrade; closes only
  the Zenv running from its own folder; refuses to report success when `zenv.exe` could not be replaced.
- Deleted: Tauri shell (`src-tauri/src`, config, capabilities, old NSIS template), React UI (`src/`, `public/`, Vite/TS config),
  npm dependencies. `src-tauri/Cargo.toml` is a virtual workspace. Verify drops tsc and Vitest.
- Review fixes: drive-root `/D` now refused (exit 2), every refusal exits 2, test builds never default to C:\zenv; owner check
  of the install folder (fails closed); the elevation check also covers files next to the exe; AUMID `dev.zenv.desktop`.
- Two racy chat tests fixed (G-025; `tests/chat.rs` 12/60 -> 0/100).

## Evidence
- `task.mjs check`: build-rust, test-rust, test-native OK.
- Installer (ZenvTest build, scratch folder): fresh install, upgrade over a running copy, locked exe (exit 2), refused folders,
  uninstall keeping data; the real C:\zenv install untouched. Release app started on C:\zenv-dev (63 MB private).

## Risks
- During qa a test build installed into the live C:\zenv (root /D dropped by NSIS): fixed here (G-026); that install still needs repair.
- Upgrading closes a running Zenv hard (services killed, as before with Tauri).
- No Prettier formatting in Studio any more (left with React).
