M20 step 8c: Claude Code chat in the native Studio window

## Summary
- New `src-native/src/studio/chat/`: the chat tab of the egui Studio, a port of the React chat (D-022): header (LED, model, pending-settings note,
  History, New chat), conversation (user bubbles, Markdown, tool cards with Allow / Always / Deny, results, notices, "Show N earlier"),
  composer (/ and @ menus, attachments by picker, drop, pasted image and Ctrl+V of files copied in Explorer, model + effort, permission mode,
  usage, Send / Stop) and the "/" palette (models, effort, thinking, fast, output styles, MCP status / toggle / reconnect, account, terminal screens).
- One worker thread per chat runs Claude Code operations in order on core's existing API (`studio_open_chat`, `studio_chat_send`, `Chats.*`);
  lines carry a generation so New chat ignores the old program's late output.
- `Terminals`: a tab is a chat or a terminal; the chat is the first tab when Claude Code is installed; "+" offers "Claude Code chat".
- Core: `ChatOptions`, `Effort`, `PermissionMode` also derive `Serialize` + `PartialEq` (saving the composer's choice).
- Direct dependencies of zenv-native (already in Cargo.lock): arboard, fancy-regex, serde, serde_json, time, windows-sys.

## Evidence
- `task.mjs check`: build-rust, typecheck, Vitest, zenv-core and zenv-native tests all OK.
- `cargo test -p zenv-native --lib -- chat:: hostile`: 31 passed; `--test chat`: 9 passed (2 ignored measurements).
- Release: 1,000-item chat 1.1 ms per frame; streaming into one 60 KB message median 8.2 ms, max 17.4 ms.
- Real window: "pong" streamed and done, History resume ("ping"), Explorer file paste, Markdown reply, palette (handoff 17-dev.md).

## Risks
- Max frame 17.4 ms while streaming a 60 KB single reply (accepted ruling).
- One unreproduced case of the "/" chip ignoring clicks in a running instance.
- Explorer paste depends on Ctrl+V still being down when the frame runs (`GetKeyState`).
